RÈGLES IMPÉRATIVES — NE JAMAIS DÉROGER
═══════════════════════════════════════════════════════
1. Réponds UNIQUEMENT en JSON valide et pur. Zéro texte avant ou après. Zéro balises Markdown (pas de ```json).
2. Extrais UNIQUEMENT ce qui est EXPLICITEMENT mentionné dans le TDR. Ne jamais inventer, déduire ou interpoler.
3. Si une section est absente du document : retourne une liste vide [] ou null selon le type — NE JAMAIS mettre des exemples fictifs.
4. "source" = citation verbatim exacte du TDR (10-30 mots max). Jamais une paraphrase.
5. "confiance" : 0.9-1.0 = explicitement mentionné | 0.6-0.89 = implicite | 0.3-0.59 = déduit | 0.0 = absent.
6. Pour experts_requis : chaque profil est une entrée séparée. Si les HM ne sont pas mentionnés → null.
7. Pour refs_exigees : extrais CHAQUE exigence de référence comme une entrée séparée, même si vague.
8. Pour qualifs_exigees : liste uniquement les certifications et accréditations institutionnelles (ISO, FIDIC, accréditations bailleur).
9. secteur_ao : détermine par les mots-clés du TDR. Valeurs : "Eau/Assainissement" | "Transport" | "Énergie" | "Urbain" | "Agriculture" | "Environnement" | "Social" | "Numérique" | "Autre".
10. type_contrat : "Forfait" | "Régie" | "Prix unitaires" | "Mixte" | "PPP" | "Autre" | null si non mentionné.
11. GARDE-FOU OCR : Si le texte est corrompu ou illisible (<300 mots, caractères aléatoires), retourne toutes les listes vides [] et ajoute une alerte "🔴 EXTRACTION TEXTE DÉFAILLANTE".
12. DOCUMENT PARTIEL : Si le document est une annexe (absence de cadre administratif), ajoute une alerte "⚠ DOCUMENT PARTIEL PROBABLE" pour avertir l'utilisateur que les tableaux vides sont liés au format du document.

═══════════════════════════════════════════════════════
GUIDE D'EXTRACTION CHAMP PAR CHAMP
═══════════════════════════════════════════════════════

refs_exigees :
  Cherche "références similaires", "expérience requise", "missions comparables", "références exigées".
  Pour chaque référence identifiée :
  — description : résumé de l'exigence (1 phrase)
  — secteur : domaine de la référence
  — duree_min_mois : durée minimale en mois (null si non mentionné)
  — budget_min_eur : budget minimum en EUR (null si non mentionné, convertir si autre devise)
  — pays_ou_region : zone géographique exigée (null si non mentionné)
  — nombre_requis : nombre de références exigées (1 par défaut si non précisé)
  — confiance : niveau de confiance de l'extraction
  — source : citation verbatim du TDR

qualifs_exigees :
  Cherche "accréditation", "certification", "norme ISO", "agrément", "qualification institutionnelle".
  Liste chaque qualification comme une chaîne de caractères.
  Si aucune qualification n'est mentionnée : retourner [].

experts_requis :
  Cherche "profil expert", "composition de l'équipe", "personnel clé", "experts requis", "Chef de Mission".
  Pour chaque expert identifié :
  — titre : intitulé exact du poste
  — specialites : liste des domaines de compétence requis
  — annees_exp_min : années d'expérience minimum (null si non mentionné)
  — langues : langues exigées (null si non mentionné)
  — hm_mission : hommes-mois alloués à ce profil (null si non mentionné)
  — confiance : niveau de confiance de l'extraction
  — source : citation verbatim du TDR
  Si aucun expert n'est mentionné : retourner [].

secteur_ao :
  Détermine le secteur principal par les mots-clés dominants du TDR. Formater en objet JSON standard (valeur, confiance, source).

type_contrat :
  Cherche "forfait", "régie", "prix unitaires", "contrat mixte", "partenariat public-privé". Formater en objet JSON standard.

conditions_resiliation :
  Extrais les clauses de résiliation : préavis, indemnités, résiliation unilatérale.
  Si absent : null. Formater en objet JSON standard.
